# 運用マニュアル

最終更新: 2026-08-23

> **この時点での位置づけ**
> 視聴ページ・管理ページとも実装済み（M1〜M4 完了）。
> 第 1〜2 章の YouTube 側の設定は、配信機材が何であれ**いま実施できる**。
> 最優先で実施してほしい。
>
> **当日は `docs/checklist.md` を印刷して持ち込むこと。** この文書は背景と理由を含む
> 詳細版で、当日その場で読むには長すぎる。
>
> **管理画面の操作は 2 種類ある。混同しないこと。**
>
> | すぐ反映される（保存不要） | 「保存」を押すまで反映されない |
> |---|---|
> | 配信の状態（配信前・配信中・中断中・終了） | 配信 URL・予備 URL・アーカイブ URL |
> | 予備 URL への切り替え | テロップ・配信前に出す文言 |
> | プログラムの「いま」の移動 | プログラムの行の追加・削除・並べ替え・文字 |
>
> 左側は**緊急時に押すボタン**なので、保存の押し忘れで反映されない事故が起きないよう
> 即時反映にしてある。

## 1. 【最優先】YouTube 側の設定

配信機材が何であれ（OBS でもスマホでもハードウェアスイッチャーでも）、
**ここの設定だけで「配信が切れて取り直しになる」事故は大きく減る。費用はゼロ。**

### 1-1. 自動終了（auto-stop）を OFF にする

YouTube Live のストリーム設定に「ストリームが停止したら配信を自動的に終了する」に
相当するトグルがある。**既定は ON**。

**これを OFF にすると、映像が途切れても配信が終了扱いにならず、
エンコーダを繋ぎ直すと同じ URL で復帰する。**

- 場所：YouTube Studio → ライブ配信 → 該当の配信 → ストリーム設定（歯車 / 編集）
- 探すキーワード：「自動終了」「auto-stop」「ストリームが停止したとき」
- YouTube の UI 文言は変更されることがあるため、上記に近い表現のトグルを探すこと

### 1-2. 再利用可能なストリームキーを使う

「エンコーダ配信」でストリームキーを作り、**再利用可能な設定**にしておく。
毎回キーを取り直す運用だと、繋ぎ直しのたびに手順が増え、1-1 の効果も薄れる。

### 1-3. 遅延は「通常の遅延」を選ぶ

「低遅延」「超低遅延」はバッファが薄く、回線の瞬断でそのまま切れる。
**保護者は数十秒の遅れを気にしない。切れないことを優先する。**

### 1-4. 公開設定と埋め込み

- 公開設定：**限定公開（unlisted）**
- **「埋め込みを許可」を ON**（これが OFF だと中継ページで映像が真っ黒になる）
- **ライブチャットは無効化**（未成年が映る配信での荒らし対策）

### 1-5. ビットレート

**720p30 / 2500kbps 程度**を推奨。画質を欲張ると回線が細いときに落ちる。
回線は可能なら有線。

### 1-6. 予備の配信を先に作っておく

**大会前日までに、限定公開の予約配信をもう 1 本作り、その URL を控えておく。**
本番が完全に死んだとき、スタッフは URL をコピペする必要すらなく、
管理画面の「予備 URL に切替」ボタンを 1 回押すだけで復旧できる。

## 1-A. Firebase 側の初期設定（管理者・一度だけ）

リポジトリは公開されるため、**書き込みを守るのはセキュリティルールだけ**である。
以下は省略できない。

- [ ] Authentication → Sign-in method → **メール/パスワード**を有効化する。
      **他のプロバイダ（Google ログイン・匿名認証など）は有効化しない**
- [ ] Authentication → ユーザー → 共有スタッフアカウントを**手動で 1 つ作成**する
      （個人のメールアドレスは使わない）
- [ ] **Authentication の設定にある「新規登録（サインアップ）を許可する」を無効化する**
      ← **この 1 項目が唯一かつ必須の防御。** これを忘れると、公開された `apiKey` を
      使って誰でもアカウントを作り、テロップや配信 URL を書き換えられる。
      設定項目の名称は Firebase Console の更新で変わることがあるため、
      Authentication → Settings 配下で「サインアップ / ユーザーの作成」に
      相当するトグルを探して無効にすること
- [ ] Realtime Database → ルール に `docs/data-model.md` のルールを貼り付けて公開
- [ ] **動作確認**：以下を実行し、すべて OK になることを確認する

```bash
node tools/check-rules.js
```

このコマンドは、無認証のクライアントから見て「読めるべきものが読めるか」
「読めてはいけないものが弾かれるか」「勝手にアカウントを作れないか」を
実際に確認する。**ルールを変更したあとは必ず実行すること。**
副作用は無い（アカウントは作られない）。

### パスワードの決め方

**メールアドレスは公開されるため、パスワードが唯一の防御線になる。**
ただしログイン状態は端末に保持され、**スタッフが入力するのは前日の 1 回だけ**なので、
覚えやすさを捨ててよい。**長いパスフレーズ**にして、前日に貼り付けてもらう。
当日の操作性は一切落ちない。

### スタッフを追加・削除するとき

共有アカウントなので、追加の手続きは不要。**前日にログインしてもらうだけ。**
スタッフが抜けた場合や漏洩が疑われる場合は、Firebase Console でパスワードを変更し、
残るスタッフに再ログインしてもらう。

## 3. 当日のスタッフ操作

> 管理画面（M2）が満たすべき操作フローの仕様を兼ねる。

### 3-1. 配信を始めるとき

1. YouTube 側で配信を開始する
2. 管理画面を開く（前日にログイン済みなら、そのまま操作できる）
3. **配信 URL の欄に、YouTube の URL を貼り付ける**
   - `https://www.youtube.com/watch?v=...` でも `https://youtu.be/...` でも
     `https://www.youtube.com/live/...` でも構わない。どの形でも受け付ける
   - 欄の下に「OK（動画 ID: …）」と出れば正しく読み取れている
4. **貼り付けると、すぐ下にプレビューが出る。ここで映像が出ていることを必ず目で確認する**
   - プレビューが真っ黒なら、YouTube 側の「埋め込みを許可」が OFF の可能性が高い
5. **「保存」を押す**（URL は保存しないと反映されない）
6. 「配信中にする」を押す（こちらは押した時点で反映される）
7. 別の端末で中継ページを開き、映っていることを確認する

### 3-2. テロップを変えるとき

テロップ欄を書き換えて「保存」。視聴者の画面は数秒で切り替わる。

### 3-3. プログラムの「いま」を動かすとき

**「次の種目へ進む」を押すだけ**でよい。押した時点で視聴者の画面に反映される（保存は不要）。
順番どおりでないときは、その行の「ここにする」を押す。

保護者が一番知りたいのは「うちの子の出番はいつか」なので、
**この操作をこまめに行うと問い合わせが減る。**

行の追加・削除・並べ替えや、時刻・内容の書き換えは「保存」を押すまで反映されない。
**プログラムを編集している最中は「いま」を動かせなくなる**（行の並びが変わると
別の種目を指してしまうため）。その場合は先に「保存」を押すこと。

### 3-3-2. コートを切り替えるとき（複数コートのみ）

管理画面の上部にコートのタブが出る。編集したいコートのタブを押す。
**タブごとに、配信 URL・テロップ・状態・プログラムがそれぞれ独立している。**

視聴者の画面にも同じタブが出る。視聴者は見たいコートを自分で選ぶ。
同時再生はしない（スマホの帯域と発熱、そして画面の見やすさのため）。

コートが 1 つだけのときはタブは出ない。

**コートの追加・削除は大会前日までに済ませること。** 当日は触らない。
未保存の変更があるあいだは、追加・削除ができないようになっている
（`courts` を丸ごと書き換えるため、未保存分を巻き添えにしないための保護）。

### 3-4. 【重要】配信が切れたとき

**あわてないこと。順番に試す。**

```
配信が切れた
 │
 ├─ ① まず「中断中にする」を押す（保存は不要。押した時点で反映）
 │     視聴者に「機材トラブルのため復旧作業中です」と出る
 │     ここで視聴者の不安はかなり収まる。最初にこれをやる
 │
 ├─ ② 機材（カメラ・ケーブル・アプリ）を繋ぎ直す
 │     ↓
 │   同じ URL で映像が戻った？
 │     ├─ 戻った → 「配信中にする」を押す。復旧完了
 │     └─ 戻らない → ③へ
 │
 ├─ ③ 「予備 URL に切り替える」を押す →「配信中にする」を押す
 │     どちらも保存は不要。予備の配信で撮影を始める
 │     視聴者の画面は自動で新しい配信に切り替わる（再読み込み不要）
 │
 └─ ④ 予備も使えない場合
       YouTube で新しくライブを作り、その URL を貼り付けて「保存」→「配信中にする」
```

**①を最初にやる理由**：視聴者は全画面で見ていることが多く、映像が止まると
何が起きたか分からない。中断中の表示を出すだけで問い合わせが激減する。

### 3-5. 視聴者の画面が切り替わらないという連絡が来たとき

**「全員の画面を再読み込み」ボタンは最終手段。**
通常は自動で切り替わるので、まず 30 秒待つ。それでも切り替わらないという報告が
複数から来た場合にだけ押す。押すと全視聴者のページが再読み込みされ、
**全画面表示が解除される**（視聴者は再度全画面にする必要がある）。

### 3-6. 配信を終えるとき

「終了にする」を押す（保存不要）。視聴者には「配信は終了しました」と出る。
アーカイブを見せる場合は、アーカイブ動画の URL を「アーカイブ」欄に入れて**「保存」を押す**。

## 4. よくあるトラブルと切り分け

| 症状 | 原因の第一候補 | 対処 |
|---|---|---|
| 中継ページで映像が真っ黒 | YouTube 側の「埋め込みを許可」が OFF | YouTube Studio で ON にする |
| 「動画は再生できません」と出る | 配信が非公開になっている / 削除された | 公開設定を限定公開に戻す |
| 一部の視聴者だけ見られない | 学校・職場のネットワークが YouTube を遮断 | **こちらでは対処不能**。別回線を案内する |
| 映像は出るが音が出ない | 視聴者側がミュートにしている | プレーヤーの音量を上げてもらう |
| 「実際の試合と違う」と言われる | 配信の遅延（数十秒〜1 分程度） | 正常。ページに注意書きあり |
| 管理画面にログインできない | パスワード誤り | 管理者に連絡。当日その場での再発行はできない |
| コートの追加・削除ボタンが押せない | 未保存の変更がある | 先に「保存」を押す |
| 文字を変えても視聴者に反映されない | 「保存」を押していない | 画面下に「未保存」の赤いバッジが出ていないか確認 |
| 「次の種目へ進む」が押せない | プログラムに未保存の変更がある | 先に「保存」を押す |

## 5. 中継ページの URL について（周知時の注意）

中継ページの URL は **誰でもアクセスできる**。
検索避け（`noindex`）はしているが、URL を知っていれば誰でも開ける。
**「URL を知っている人だけが見られる」は保護ではなく目隠しである。**

配信そのものの制限は YouTube の限定公開設定で行っている。
それ以上の制限が必要になった場合は、静的サイトの範囲では実現できないため、
仕組みから見直す必要がある（`docs/requirements.md` HC-4）。

被写体（未成年を含む）の撮影・配信についての同意取得は、
システムではなく運営側の責任範囲である。

## 6. 【スタッフ全員へ】入力した内容は誰でも見られます

**テロップ・プログラム・お知らせに入力した内容は、中継ページを開かなくても
誰でも取得できます。** 中継ページの仕組み上、これを非公開にすることはできません。

したがって、**選手名・出場者の所属・学校名・スタッフの連絡先を入力しないでください。**

| 入れてよい | 入れてはいけない |
|---|---|
| 「小学3・4年 形」 | 「山田太郎 選手」 |
| 「第1コート」 | 「○○小学校チーム」 |
| 「10:40 から組手を配信します」 | 「係の携帯 090-…」 |

システム側でこれを機械的に防ぐことはできません。**入力する人の判断が最後の防波堤です。**
管理画面には注意書きを常時表示しますが、それは思い出すためのものであって、
止めてくれるものではありません。

## 付録. 他団体でこの仕組みを使う場合

このリポジトリは特定の団体に依存しないよう作られている。

1. リポジトリをフォークする
2. 自分の Firebase プロジェクトを作り、第 1-A 章の初期設定を行う
3. `config.sample.json` をコピーして `config.json` を作り、
   Firebase の接続設定・スタッフアカウントのメールアドレス・サイト名・
   公式サイト URL・退避時の連絡先を書き換える
4. GitHub Pages を有効にする

**書き換えるのは `config.json` だけ**である。ソースコードに団体固有の値は入っていない
（`docs/requirements.md` REQ-161）。
